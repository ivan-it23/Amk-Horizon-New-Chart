# AMK-Horizon-New-Chart

**Статус документации:** актуально для ветки `main`, текущего adapter-driven parsing pipeline, canonical `GP_TOOL_DATA` / `METROLOGY_DATA` (240 байт), поддерживаемых сигнатур `151` / `152` / `241` и протокола `0x11/0x12/0x13/0x16/0x17`

## Описание проекта

AMK-Horizon-New-Chart - это Windows-приложение для визуализации и анализа данных геофизических приборов. Приложение предназначено для отображения многоканальных данных в виде интерактивных графиков с поддержкой различных типов измерений (амплитуды в милливольтах, фазы в миллиградусах, отношения, разности).

## Назначение

Приложение используется для:
- **Визуализации данных** с геофизических приборов в реальном времени
- **Чтения данных с прибора** через COM-порт в режиме реального времени
- **Анализа многоканальных измерений** (T1-T5 передатчики, R1-R2 приемники)
- **Сравнения различных типов данных** (амплитуды, фазы, отношения, разности)
- **Интерактивного масштабирования** и навигации по данным
- **Настройки отображения** через схему прибора

## 🏗️ Архитектура

Проект построен на **модульной архитектуре** с четким разделением ответственности:

```
┌─────────────────┐
│   ChartManager  │ ← Главный координатор
└─────────────────┘
         │
    ┌────┴────┐
    │ Модули  │
    └────┬────┘
         │
┌────────┼────────┐
│        │        │
▼        ▼        ▼
DataModule  ChartModule  UIModule
    │           │           │
    ▼           ▼           ▼
LayoutModule  SchematicModule  CurveSelectionModule
MetrologyModule SerialModule
```
### Основные модули:

- **DataModule** - управление данными прибора
- **ChartModule** - отрисовка графиков и визуализация
- **UIModule** - пользовательский интерфейс
- **LayoutModule** - компоновка интерфейса
- **SchematicModule** - схема прибора и выбор элементов
- **CurveSelectionModule** - управление кривыми и пресетами
- **SerialModule** - работа с COM-портом, протокол обмена, запись потока в файл, команды метрологии/selected_key
- **MetrologyModule** - загрузка/сохранение метрологии, проверка signature и работа с формой метрологии

### Актуальный data pipeline

Текущее прохождение данных в проекте выглядит так:

`File/COM -> signature detection -> ToolDataAdapterRegistry -> ParsedToolFrame -> canonical GP_TOOL_DATA + ToolRecordMetadata -> ToolDataAccessView / MeasurementView -> chart/UI logic`

Ключевые инварианты текущей реализации:

- файл и COM-поток уже маршрутизируются через `ToolDataAdapterRegistry`
- realtime ingest в основном live-path идёт как `SerialModule -> ChartManager -> DataModule::AddParsedData(...)`
- верхний слой постепенно опирается на `MeasurementView` и `ToolDataAccessView`, а не на прямой доступ к сырым массивам
- canonical `GP_TOOL_DATA` всё ещё остаётся основным compatibility storage/API shape
- публичные GP-level API `GetData()`, `ParseRawFrame(...)`, `RequestData(GP_TOOL_DATA& ...)`, `SetDataCallback(...)` сейчас рассматриваются как compatibility-only surface-ы

## 🚀 Основные возможности

### 📊 Визуализация данных
- **Одиночный и двойной режимы** отображения графиков
- **Zoom и скроллинг по обеим осям** (X и Y) для детального анализа
- **Многоканальные данные** (T1-T5 передатчики)
- **Различные типы измерений**:
  - Phase Difference (разности фаз R2−R1 в миллиградусах, мдег)
  - Amplitude Ratios (отношения амплитуд RX2/RX1, безразмерные)
  - Amplitude RX1/RX2 (амплитуды приёмников в милливольтах, мВ)
  - Silent Amplitude RX1/RX2 (амплитуды в молчащем режиме, мВ)
  - Temperature (температура, °C)
- **Физические единицы измерения**:
  - Амплитуды: милливольты (мВ) - преобразование из сырых данных АЦП
  - Фазы: миллиградусы (мдег) - преобразование из радианов для удобства анализа

### 🎛️ Интерактивность
- **Режим Surf** (v2.14.0) - автоматическое отслеживание последних N точек
- **Масштабирование** областей графика (zoom по X и Y)
- **Прокрутка** по горизонтали и вертикали
- **Вертикальный scrollbar** для навигации по оси Y
- **Выбор отображаемых кривых** через окно **Device Schematic**
- **Сброс масштаба** правой кнопкой мыши (по обеим осям)

### ⚙️ Настройка через схему прибора
- **Визуальная схема** с элементами T1-T5, R1-R2, Silent
- **Быстрые пресеты**:
  - All Ampl RX1 / All Ampl RX2 - все амплитуды для приемника
  - Amplitude Ratios - отношения амплитуд
  - Phase Difference - разности фаз
  - Temperature - температура
- **Копирование настроек** между графиками
- **Выбор частоты** (400 kHz / 2000 kHz)

### 🧪 Метрология (AUTONOM 5Tx)
- **Немодальное окно метрологии** из меню прибора
- **Кнопки**: открыть файл, сохранить файл, прочитать из зонда, записать в зонд, записать команду (`selected_key`)
- **Формат файла метрологии**: стабильные 240 байт (`METROLOGY_DATA`)
- **Подпись signature**: совместимая с legacy-схемой (mod + number, number до 999)
- **Проверка совместимости**: поддерживаются signature типов AUTONOM 5Tx (`151`/`152`)

### 📈 Система кривых
- **Автоматическое определение** доступных кривых
- **Двойные оси** для разных типов данных
- **Цветовое кодирование** каналов
- **Легенда** с единицами измерения

## 🔧 Технические детали

### Платформа
- **Windows API** (Win32)
- **Visual C++** (MSVC)
- **GDI** для отрисовки графиков

### Форматы данных (v2.16.x)
- **Поддерживаемые расширения**: `.bin`, `.biv`, `.DEV`
- **Adapter-driven parsing**: выбор формата/структуры идёт по `signature` через `ToolDataAdapterRegistry`
- **Canonical storage shape**: после парсинга данные пока сохраняются как `GP_TOOL_DATA` + `ToolRecordMetadata`
- **Актуальная основная UI/graph модель**: 5 передатчиков (T1–T5), 2 частоты (400 kHz, 2000 kHz)
- **Валидация при открытии файла**: проверяются расширение, сигнатура, декодированный тип прибора и кратность физическому размеру кадра
- **Поддерживаемые сигнатуры**: `AUTONOM_5Tx (151)`, `AUTONOM_5Tx_SDR (152)`, `LWD_4Tx (241)`
- **Важно**: `LWD_4Tx` уже поддерживается на уровне adapter parsing и canonical materialization, но верхняя UI/SMT-логика всё ещё во многом сохраняет 5Tx-centric contract

| Формат | Описание | Размер блока |
|--------|----------|--------------|
| .bin   | Последовательность GP_TOOL_DATA | 240 байт |
| .biv   | Идентичен .bin | 240 байт |
| .DEV   | 11-байтный заголовок + GP_TOOL_DATA | 251 байт |

## 🚀 Быстрый старт

### Сборка проекта
1. Откройте `Amk-Horizon-New-Chart.vcxproj` в Visual Studio
2. Выберите конфигурацию Debug/Release x64
3. Соберите проект (Build → Build Solution)

### Запуск
1. Запустите `Amk-Horizon-New-Chart.exe`
2. Загрузите файл данных (File → Open Data File, поддерживаются `.bin`, `.biv`, `.DEV`) или подключитесь к прибору
3. Настройте отображение через Device Schematic

## 📡 Работа с прибором в реальном времени

### Подключение к прибору
1. Откройте меню **Прибор** → **Подключить...**
2. В диалоге выберите COM-порт из списка
3. Нажмите **Подключить** для установки соединения
4. При успешном подключении отобразится информация о приборе (серийный номер, диаметр зонда)
5. Опрос данных начнётся автоматически

### Управление подключением
- **Прибор → Подключить...** - открыть диалог подключения
- **Прибор → Отключить** - отключиться от прибора
- **Прибор → Старт опроса** - начать периодический опрос
- **Прибор → Стоп опроса** - остановить опрос
- **Прибор → Очистить данные** - удалить накопленные данные

### Диалог подключения
- **COM-порт** - выбор порта из списка доступных
- **Обновить** - обновить список COM-портов
- **Подключить/Отключить** - управление соединением
- **Статус** - текущее состояние (Отключено/Подключено/Опрос...)
- **Кадр** - номер последнего полученного кадра
- **Пакеты** - статистика (получено / ошибок)
- **Очистить данные** - удалить накопленные данные
- **Сворачивание/повторное открытие**: окно можно сворачивать; закрытие скрывает окно; повторный вызов из меню восстанавливает уже активный экземпляр с актуальной онлайн-информацией

### Протокол обмена
- Скорость: **125000 бод**
- Интервал опроса: **2 секунды**
- Команда данных: **0x11 (CMD_DATA)**
- Команда записи метрологии: **0x12 (CMD_SET_METROLOGY)**
- Команда метрологии: **0x13 (CMD_GET_METROLOGY)**
- Команда сигнатуры: **0x16 (CMD_GET_SIGNATURE)**
- Команда selected key: **0x17 (CMD_SET_SELECTED_KEY)**
- Проверка целостности: **CRC16 Modbus**
Используйте быстрые пресеты или настройте кривые вручную.

## 🤝 Разработка

- **Модульность** - четкое разделение ответственности
- **Актуальность документации** - опорные документы должны описывать текущее поведение, а не historical drift
- **Минимум дублирования** - обзорные документы фиксируют текущее поведение, а подробный статус миграции и boundary decisions хранится в `ADAPTER_REGISTRY_IMPLEMENTATION_PLAN.md`
