## ✨ Версия 2.6.0 - Улучшения интерфейса и сохранения данных

### ✨ Улучшения интерфейса

#### Частота в заголовке вместо "(Custom Curves)"
- **Проблема**: Заголовок графика всегда содержал подпись "(Custom Curves)", которая не несла полезной информации и не помогала в анализе данных.
- **Решение**: 
  - Заголовок теперь отображает частоту: **"Chart 1 (400 kHz)"** или **"Chart 2 (2000 kHz)"**
  - Частота берется из конфигурации кривых, выбранной в Device Schematic
  - Если данные не загружены, отображается просто **"Chart 1"** без скобок
- **Результат**: Сразу видно, на какой частоте отображаются данные, легче сравнивать графики с разными частотами.

#### Преимущества
- **Информативность** - не нужно открывать Device Schematic для проверки частоты
- **Удобство анализа** - при работе с Dual Mode легко различить частоты графиков
- **Чистота интерфейса** - убрана избыточная подпись, заголовок содержит только полезную информацию
- **Согласованность** - частота в заголовке соответствует выбору в Device Schematic

#### Примеры отображения
- **С частотой 400 kHz**: "Chart 1 (400 kHz)"
- **С частотой 2000 kHz**: "Chart 2 (2000 kHz)"
- **Без конфигурации**: "Chart 1" (без скобок)

#### Технические изменения
- **ChartManager.cpp** - метод `DrawChartWithCurves()` обновлен для формирования заголовка с частотой
- Частота извлекается из первой кривой конфигурации: `config.curves[0].frequency`
- Автоматическое обновление при изменении конфигурации в Device Schematic

### ✨ Улучшения сохранения данных

#### Информативные имена файлов при сохранении диапазона
- **Проблема**: При сохранении диапазона предлагалось общее имя `data_range_5000_6000.bin`, которое не содержало информации об исходном файле и дате сохранения.
- **Решение**:
  - Имя файла формируется автоматически по шаблону: `[исходное_имя]_range_[начало]_[конец]_[ДД_ММ_ГГГГ].bin`
  - Пример: `measurement_2025_11_03_range_5000_6000_03_11_2025.bin`
  - Имя исходного файла сохраняется при загрузке данных
  - Добавляется текущая дата в формате ДД_ММ_ГГГГ
- **Результат**: Сразу видно из какого файла сохранен диапазон, какой участок данных и когда.

#### Преимущества
- **Информативность** - имя файла содержит всю необходимую информацию
- **Отслеживаемость** - легко найти нужный файл среди множества сохраненных диапазонов
- **Уникальность** - дата в имени предотвращает случайную перезапись
- **Контекст** - не нужно открывать файл, чтобы понять его содержимое

#### Технические изменения
- **DataModule** - добавлена переменная `loadedFileName` для хранения имени файла
- **DataModule::LoadDataFromFile()** - сохраняет имя загруженного файла (без пути и расширения)
- **DataModule::GetLoadedFileName()** - новый метод для получения имени файла
- **ChartManager::HandleSaveRange()** - формирует имя файла с использованием исходного имени и даты

## ✨ Версия 2.4.0 - Горизонтальная легенда графиков

### ✨ Улучшения интерфейса

#### Горизонтальное расположение легенды
- **Проблема**: При большом количестве кривых вертикальная легенда в правом верхнем углу перекрывала данные графика, затрудняя чтение подписей и анализ данных.
- **Решение**:
  - Легенда перемещена **вверх графика** (между заголовком и областью данных)
  - Элементы легенды располагаются **горизонтально** (в строку)
  - **Выравнивание по центру** - подписи равномерно распределены по ширине графика
  - Автоматический перенос на новую строку при необходимости
- **Результат**: Легенда больше не перекрывает данные графика, улучшена читаемость и удобство анализа.

#### Разделители и подписи осей для двойных осей
- **Проблема**: При отображении графиков с двойными осями (например, амплитуды + фазы) было неясно, какие кривые к какой оси относятся.
- **Решение**:
  - Добавлены подписи осей с единицами измерения: `[Left Axis (mV)]` и `[Right Axis (mdeg)]`
  - Визуальный разделитель `|` между группами кривых
  - Четкая группировка: сначала все кривые левой оси, затем разделитель, затем кривые правой оси
  - **Убраны цветные квадраты** - оставлены только цветные линии, показывающие стиль (сплошная/пунктирная)
- **Формат**: `[Left Axis (mV)] ━ T1 Ampl ━ T2 Ampl | [Right Axis (mdeg)] ┄ T1 Phase ┄ T2 Phase`
- **Результат**: Полная ясность, какие кривые к какой оси относятся, улучшена читаемость и понимание данных.

#### Упрощение легенды - только линии
- **Проблема**: Дублирование информации о цвете - и квадрат, и линия показывали один и тот же цвет кривой.
- **Решение**: Убраны цветные квадраты, оставлены только цветные линии
- **Преимущества**:
  - Линия показывает И цвет, И стиль (сплошная для левой оси, пунктирная для правой)
  - Визуальное соответствие - линия в легенде = линия на графике
  - Более компактная легенда
  - Меньше визуального шума
- **Формат обычных графиков**: `☑ ━ T1  ☑ ━ T2  ☑ ━ T3  ☑ ━ T4`
- **Формат двойных осей**: `[Left Axis] ━ T1 Ampl | [Right Axis] ┄ T1 Phase`

#### Применено к
- **Обычные графики** - легенда с чекбоксами для T1-T4
- **Графики с двойными осями** - легенда с разделителями и подписями осей
- Сохранена интерактивность чекбоксов для включения/выключения каналов

#### Преимущества
- Легенда не перекрывает данные графика
- Четкое разделение кривых по осям для двойных осей
- Подписи единиц измерения для каждой оси
- Лучшая читаемость подписей кривых
- Более эффективное использование пространства
- Удобство при работе с большим количеством кривых
- Современный и чистый интерфейс

#### Технические изменения
- **ChartModule.cpp** - переработаны методы:
  - `DrawChartLegend()` - горизонтальное расположение с центрированием
  - `DrawDualAxisLegend()` - горизонтальное расположение с разделителями и подписями осей
  - `HitTestLegendCheckbox()` - обновлена логика определения кликов по чекбоксам
  - `CalculatePlotRect()` - увеличен верхний отступ (40→65px) для легенды
  - `CalculateDualAxisPlotRect()` - увеличен верхний отступ (40→65px) для легенды

## ✨ Версия 2.3.0 - Нормализация фазовых данных

### ✨ Новые возможности

#### Нормализация фаз в диапазон (-π, π]
- **Назначение**: Приведение фазовых данных к стандартному диапазону (-π, π] для корректного отображения циклических фазовых сигналов в индукционном каротаже.
- **Реализация**:
  - Добавлен метод `NormalizePhase()` в DataModule для нормализации фазы в радианах
  - Алгоритм: `while (phase > π) phase -= 2π; while (phase ≤ -π) phase += 2π;`
  - Применяется **перед** преобразованием в миллиградусы
- **Применено к**:
  - **PHASE_DIFFERENCE** - разности фаз между приемниками (R2-R1)
  - **PHASE_RX1** - фазы приемника 1 для всех передатчиков T1-T4
  - **PHASE_RX2** - фазы приемника 2 для всех передатчиков T1-T4
  - Для обеих частот: 400 kHz и 2000 kHz
- **Результат**: Фазовые данные корректно отображаются в диапазоне от -180000 мдег до +180000 мдег без скачков и разрывов.

#### Физический смысл
- **Циклическая природа фазы**: Фаза 370° эквивалентна 10°, фаза -370° эквивалентна -10°
- **Устранение скачков**: Нормализация предотвращает резкие скачки на графиках при переходе через границы ±π
- **Специфика индукционного каротажа**: Учитывает особенности фазовых измерений геофизических приборов

#### Преимущества
- Корректное отображение циклических фазовых сигналов
- Устранение артефактов и скачков на графиках
- Соответствие стандартам обработки данных индукционного каротажа
- Сохранение всех данных (в отличие от обнуления)
- Полная обратная совместимость с существующими данными

#### Технические изменения
- **DataModule.h** - добавлен метод `float NormalizePhase(float phaseRadians) const;`
- **DataModule.cpp** - реализация метода нормализации и применение в:
  - `CalculateChartData()` - для PHASE_DIFFERENCE, PHASE_RX1, PHASE_RX2
  - `CalculateDifferenceData()` - для разностей фаз
  - `CalculatePhaseData()` - для фаз приемников

#### Порядок обработки фазовых данных
1. Чтение сырых данных фазы в радианах из файла
2. **Нормализация** в диапазон (-π, π] с помощью `NormalizePhase()`
3. Преобразование в миллиградусы (* 57295.7795f)
4. Отображение на графике

- Все подписи видны полностью - нет обрезания текста
- Аккуратный интерфейс - подписи выровнены по оси Y
- Универсальность - работает для любых значений (коротких и длинных)

- Высокая точность - миллиградусы обеспечивают точность
- Удобство анализа - не нужно конвертировать вручную
- Полная обратная совместимость

## ✨ Версия 2.2.2 - Преобразование единиц измерения амплитуд

#### Изменены единицы измерения амплитуд с Вольтов на милливольты

  - AMPLITUDE_RATIO не изменён (безразмерная величина V/V)
- **Результат**: Значения на графике отображаются в физических единицах (милливольтах), улучшено масштабирование и читаемость.

#### Преимущества
- Лучшая читаемость - меньше цифр, проще анализировать
- Улучшенное масштабирование графика
- Стандартные единицы для электроники
- Полная обратная совместимость - исходные данные не изменяются

#### Технические изменения
- **CurveSelectionModule.cpp** - изменены единицы "V" → "mV" в методах CreateAmplitudeCurve() и CreateSilentAmplitudeCurve()
- **DataModule.cpp** - применена формула преобразования `value * 4000.0f / pow(2.0f, 24.0f)` в методах CalculateChartData(), CalculateAmplitudeData(), CalculateSilentAmplitudeData()

## 🐛 Версия 2.1.4 - Исправление сохранения выбора приёмников R1/R2

### 🐛 Критическое исправление

#### Проблема с сохранением выбора приёмников в Device Schematic
- **Проблема**: При выборе приёмников R1 или R2 (по отдельности или вместе R1+R2) они корректно выделялись как активные элементы. Однако при повторном открытии диалога Device Schematic приёмники не выделялись, вместо них выделялись передатчики T1-T4.
- **Причина**: Когда выбран приёмник R1/R2, система генерирует кривые для **всех 4 передатчиков** (T1-T4). При восстановлении конфигурации код видел `sourceElement = TRANSMITTER` для всех 4 передатчиков и ошибочно восстанавливал передатчики вместо приёмников.
- **Ключевое отличие**:
  - Выбор приёмника R1/R2: кривые для **ВСЕХ 4 передатчиков**
  - Выбор передатчиков: кривые только для **ВЫБРАННЫХ передатчиков**

#### Решение
- Добавлен подсчёт уникальных передатчиков в кривых (`std::set<int> uniqueTransmitters`)
- Улучшена логика определения выбора:
  - Если `uniqueTransmitters.size() == 4` и есть только типы RX1 или RX2 → восстанавливается приёмник
  - Если `uniqueTransmitters.size() < 4` и есть типы RX1 и RX2 → восстанавливаются передатчики
  - Если `uniqueTransmitters.size() == 4` и есть типы RX1 и RX2 → проверяется количество кривых для определения

#### Технические изменения
- **SchematicModule.cpp**:
  - Добавлен `#include <set>`
  - Переработан метод `InitializeDialogControls()` с улучшенной логикой восстановления
  - Добавлена отладочная информация для отслеживания процесса восстановления

#### Тестовые сценарии
- ✅ Выбор R1 → повторное открытие → R1 выделен
- ✅ Выбор R2 → повторное открытие → R2 выделен
- ✅ Выбор R1+R2 → повторное открытие → R1 и R2 выделены
- ✅ Выбор передатчиков → повторное открытие → передатчики выделены (проверка регрессии)
