## ✨ Версия 2.2.2 - Преобразование единиц измерения амплитуд

### ✨ Улучшения отображения данных

#### Изменены единицы измерения амплитуд с Вольтов на милливольты
- **Проблема**: Значения амплитуд отображались в сырых данных АЦП, что затрудняло интерпретацию и анализ данных.
- **Решение**:
  - Изменены единицы измерения с "V" на "mV" (милливольты)
  - Применена специальная формула преобразования: `значение * 4000.0f / pow(2.0f, 24.0f)`
  - Формула учитывает разрядность АЦП (24 бита) и диапазон измерения (4000 мВ)
  - Применено к AMPLITUDE_RX1, AMPLITUDE_RX2, SILENT_AMPLITUDE_RX1, SILENT_AMPLITUDE_RX2
  - AMPLITUDE_RATIO не изменён (безразмерная величина V/V)
- **Результат**: Значения на графике отображаются в физических единицах (милливольтах), улучшено масштабирование и читаемость.

#### Преимущества
- Лучшая читаемость - меньше цифр, проще анализировать
- Улучшенное масштабирование графика
- Стандартные единицы для электроники
- Полная обратная совместимость - исходные данные не изменяются

#### Технические изменения
- **CurveSelectionModule.cpp** - изменены единицы "V" → "mV" в методах CreateAmplitudeCurve() и CreateSilentAmplitudeCurve()
- **DataModule.cpp** - применена формула преобразования `value * 4000.0f / pow(2.0f, 24.0f)` в методах CalculateChartData(), CalculateAmplitudeData(), CalculateSilentAmplitudeData()

## ✨ Версия 2.2.1 - Упрощение выделения области при Zoom

### ✨ Визуальные улучшения

#### Удалена диагональная штриховка из прямоугольника выделения при zoom

  - Прозрачная заливка (`NULL_BRUSH`) - график полностью виден
- **Результат**: Прямоугольник выделения показывает только рамку, график внутри полностью виден, выделение области стало точнее и понятнее.

#### Преимущества
- Лучшая видимость данных графика - ничто не перекрывает данные
- Точное выделение области - легче видеть границы
- Меньше визуального шума - чистый минималистичный интерфейс
- Быстрее отрисовка - нет цикла рисования диагональных линий
- Проще код - удалено ~40 строк кода

## ✨ Версия 2.1.5 - Улучшение видимости выделения области при Zoom

### ✨ Визуальные улучшения

#### Изменён цвет и стиль прямоугольника выделения при zoom с добавлением диагональной штриховки
- **Проблема**: При выделении области курсором для увеличения (zoom) использовался синий цвет в режиме `R2_XORPEN`, который недостаточно контрастен и плохо виден на графиках. Первая попытка с обычной отрисовкой вызывала мигание. Режим `R2_NOT` скрывал сетку графика внутри выделения.
- **Решение**: 
  - Изменён цвет на яркий оранжевый `RGB(255, 140, 0)` для рамки
  - Добавлен пунктирный стиль линии для рамки (8px линия, 4px пробел)
  - Добавлена диагональная оранжевая штриховка (шаг 15px) для лучшей визуализации области
  - Изменён режим отрисовки на `R2_NOTXORPEN` для XOR эффекта без скрытия сетки
  - Сохранён XOR подход для избежания мигания графиков
- **Результат**: Прямоугольник выделения ярко виден на любом фоне, диагональная штриховка четко показывает область с эффектом полупрозрачности, сетка графика видна, отсутствует мигание.

#### Преимущества
- Более яркий и контрастный оранжевый цвет
- Пунктирная рамка хорошо видна на любом фоне
- Диагональная штриховка четко показывает выделенную область
- Эффект полупрозрачности не перекрывает данные полностью
- Профессиональный внешний вид
- Сетка графика видна внутри выделения
- Отсутствие мигания графиков (XOR подход)
- Не конфликтует с цветами кривых T1-T4
- Плавная отрисовка без перерисовки всего графика

#### Технические изменения
- **ChartModule.cpp** - метод `DrawZoomRectangle()` обновлён (режим `R2_NOTXORPEN`, пунктирная оранжевая линия)
- **ChartManager.cpp** - методы `HandleMouseMove()`, `HandleMouseUp()` восстановлены с XOR подходом

## 🐛 Версия 2.1.4 - Исправление сохранения выбора приёмников R1/R2

### 🐛 Критическое исправление

#### Проблема с сохранением выбора приёмников в Device Schematic
- **Проблема**: При выборе приёмников R1 или R2 (по отдельности или вместе R1+R2) они корректно выделялись как активные элементы. Однако при повторном открытии диалога Device Schematic приёмники не выделялись, вместо них выделялись передатчики T1-T4.
- **Причина**: Когда выбран приёмник R1/R2, система генерирует кривые для **всех 4 передатчиков** (T1-T4). При восстановлении конфигурации код видел `sourceElement = TRANSMITTER` для всех 4 передатчиков и ошибочно восстанавливал передатчики вместо приёмников.
- **Ключевое отличие**:
  - Выбор приёмника R1/R2: кривые для **ВСЕХ 4 передатчиков**
  - Выбор передатчиков: кривые только для **ВЫБРАННЫХ передатчиков**

#### Решение
- Добавлен подсчёт уникальных передатчиков в кривых (`std::set<int> uniqueTransmitters`)
- Улучшена логика определения выбора:
  - Если `uniqueTransmitters.size() == 4` и есть только типы RX1 или RX2 → восстанавливается приёмник
  - Если `uniqueTransmitters.size() < 4` и есть типы RX1 и RX2 → восстанавливаются передатчики
  - Если `uniqueTransmitters.size() == 4` и есть типы RX1 и RX2 → проверяется количество кривых для определения

#### Технические изменения
- **SchematicModule.cpp**:
  - Добавлен `#include <set>`
  - Переработан метод `InitializeDialogControls()` с улучшенной логикой восстановления
  - Добавлена отладочная информация для отслеживания процесса восстановления

#### Тестовые сценарии
- ✅ Выбор R1 → повторное открытие → R1 выделен
- ✅ Выбор R2 → повторное открытие → R2 выделен
- ✅ Выбор R1+R2 → повторное открытие → R1 и R2 выделены
- ✅ Выбор передатчиков → повторное открытие → передатчики выделены (проверка регрессии)
