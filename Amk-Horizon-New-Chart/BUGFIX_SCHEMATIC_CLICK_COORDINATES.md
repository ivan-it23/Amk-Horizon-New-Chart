# 🐛 Исправление координат кликов в Device Schematic

**Дата**: 5 ноября 2025  
**Версия**: 2.6.1

## 📋 Описание проблемы

### Симптомы
При работе с диалогом Device Schematic наблюдалась проблема с областью клика на кнопки элементов прибора:
- **Визуальное отображение**: Кнопки элементов (T1-T4, R1-R2, Silent 1-2) отрисовывались в определённых координатах
- **Область клика**: Находилась **НИЖЕ** визуального положения кнопок
- **Результат**: 
  - Клик непосредственно на видимую кнопку → ничего не происходит
  - Клик ниже кнопки (где курсор превращается в "руку") → кнопка активируется/деактивируется

### Причина
**Рассинхронизация координат** между:
1. **Отрисовкой элементов** (`RenderSchematic()`) - элементы рисуются в абсолютных координатах области схемы
2. **Обработкой кликов** (`WM_LBUTTONDOWN`) - координаты клика неправильно преобразовывались

## 🔍 Техническая причина

### Проблемный код (ДО исправления)

```cpp
case WM_LBUTTONDOWN:
    {
        int x = LOWORD(lParam);  // Координаты в системе диалога
        int y = HIWORD(lParam);
        
        HWND hSchematicArea = GetDlgItem(hDlg, IDC_SCHEMATIC_AREA);
        if (hSchematicArea) {
            RECT schematicRect;
            GetClientRect(hSchematicArea, &schematicRect);
            MapWindowPoints(hSchematicArea, hDlg, (POINT*)&schematicRect, 2);
            
            POINT pt = {x, y};
            if (PtInRect(&schematicRect, pt)) {
                // ❌ ОШИБКА: Вычитаем смещение, хотя элементы уже в абсолютных координатах
                x -= schematicRect.left;
                y -= schematicRect.top;
                
                pSchematic->HandleElementClick(x, y);  // Передаем неправильные координаты
            }
        }
    }
```

### Логика координат

**Система координат элементов** (`CalculateElementRect`):
- Элементы рассчитываются в координатах, которые **включают** смещение `schematicRect.left/top`
- Пример: Если `schematicRect.left = 10`, то элемент T1 может иметь `rect.left = 50` (абсолютная координата)

**Система координат клика** (`WM_LBUTTONDOWN`):
- `LOWORD(lParam)` и `HIWORD(lParam)` возвращают координаты **относительно окна диалога**
- Эти координаты уже находятся в той же системе, что и координаты элементов

**Проблема**:
- Код вычитал `schematicRect.left/top` из координат клика
- Это приводило к **двойному смещению**: элементы уже учитывали смещение, а мы вычитали его еще раз
- Результат: область клика смещалась вниз и вправо относительно визуального положения кнопок

## ✅ Решение

### Исправленный код

```cpp
case WM_LBUTTONDOWN:
    {
        int x = LOWORD(lParam);  // Координаты в системе диалога
        int y = HIWORD(lParam);
        
        HWND hSchematicArea = GetDlgItem(hDlg, IDC_SCHEMATIC_AREA);
        if (hSchematicArea) {
            RECT schematicRect;
            GetClientRect(hSchematicArea, &schematicRect);
            MapWindowPoints(hSchematicArea, hDlg, (POINT*)&schematicRect, 2);
            
            POINT pt = {x, y};
            if (PtInRect(&schematicRect, pt)) {
                // ✅ ИСПРАВЛЕНО: Координаты клика уже в системе координат диалога,
                // а элементы в schematicElements хранят координаты относительно schematicRect
                // Поэтому НЕ нужно вычитать смещение - передаем координаты как есть
                
                pSchematic->HandleElementClick(x, y);  // Передаем правильные координаты
            }
        }
    }
```

### Аналогичное исправление для WM_MOUSEMOVE

Та же проблема была в обработчике `WM_MOUSEMOVE` (для hover эффекта):

```cpp
case WM_MOUSEMOVE:
    {
        int x = LOWORD(lParam);
        int y = HIWORD(lParam);
        
        HWND hSchematicArea = GetDlgItem(hDlg, IDC_SCHEMATIC_AREA);
        if (hSchematicArea) {
            RECT schematicRect;
            GetClientRect(hSchematicArea, &schematicRect);
            MapWindowPoints(hSchematicArea, hDlg, (POINT*)&schematicRect, 2);
            
            POINT pt = {x, y};
            if (PtInRect(&schematicRect, pt)) {
                // ✅ ИСПРАВЛЕНО: НЕ вычитаем смещение
                pSchematic->HandleMouseHover(hDlg, x, y);
            }
        }
    }
```

## 📝 Примечания

### Почему проблема не была замечена раньше?
- Смещение было небольшим (10-50 пикселей)
- Пользователи интуитивно кликали чуть ниже кнопок и привыкли к этому поведению
- Hover эффект подсказывал, где нужно кликать

### Почему исправление простое?
- Проблема была в **одной строке кода** (вычитание смещения)
- Логика координат элементов была правильной изначально
- Требовалось только убрать лишнее преобразование координат
