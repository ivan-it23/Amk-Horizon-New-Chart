# 💾 Сохранение диапазона данных - Версия 2.5.0

## 📋 Обзор

Функция сохранения выбранного диапазона данных позволяет экспортировать часть загруженного файла в отдельный бинарный файл для последующего анализа.

## 🎯 Назначение

### Проблема
При работе с большими файлами данных (например, 10000 записей) часто требуется сохранить только интересующий участок для:
- Детального анализа конкретного события
- Передачи коллегам для обсуждения
- Создания примеров данных
- Уменьшения размера файла

### Решение
Реализована функция "Save Range", которая:
1. Использует текущий X Range (заданный пользователем)
2. Извлекает записи из указанного диапазона
3. Сохраняет их в новый бинарный файл
4. Сохраненный файл можно открыть как обычный файл данных

## 🔧 Техническая реализация

### Формат имени файла (обновлено v2.6.0)

Имя сохраненного файла формируется автоматически по шаблону:
```
[исходное_имя]_range_[начало]_[конец]_[ДД_ММ_ГГГГ].bin
```

**Компоненты имени:**
- `[исходное_имя]` - имя загруженного файла без пути и расширения
- `range` - ключевое слово, указывающее на сохраненный диапазон
- `[начало]` - начальный индекс диапазона (startIndex)
- `[конец]` - конечный индекс диапазона (endIndex)
- `[ДД_ММ_ГГГГ]` - дата сохранения в формате день_месяц_год

**Примеры:**
- Исходный файл: `measurement_2025_11_03.bin`, диапазон 5000-6000, дата 03.11.2025
  - Результат: `measurement_2025_11_03_range_5000_6000_03_11_2025.bin`
- Исходный файл: `test_data.bin`, диапазон 100-200, дата 15.12.2025
  - Результат: `test_data_range_100_200_15_12_2025.bin`

**Преимущества:**
- Сразу видно из какого файла сохранен диапазон
- Понятно какой участок данных содержится (начало и конец)
- Дата сохранения помогает отслеживать версии
- Уникальное имя предотвращает случайную перезапись

### Новые компоненты

#### 1. DataModule::SaveDataRange()
```cpp
bool SaveDataRange(const std::wstring& filename, size_t startIndex, size_t endIndex) const;
```

**Назначение**: Сохранение диапазона записей в бинарный файл

**Параметры**:
- `filename` - путь к файлу для сохранения
- `startIndex` - начальный индекс (включительно)
- `endIndex` - конечный индекс (включительно)

**Возвращает**: `true` при успехе, `false` при ошибке

**Алгоритм**:
```cpp
1. Проверка корректности индексов
2. Открытие файла для записи (std::ofstream, binary mode)
3. Запись записей data[startIndex] ... data[endIndex]
4. Закрытие файла
```

**Формат файла**: Идентичен исходному - последовательность структур `GP_TOOL_DATA`

#### 1a. DataModule::GetLoadedFileName() (новое v2.6.0)
```cpp
std::wstring GetLoadedFileName() const;
```

**Назначение**: Получение имени загруженного файла без пути и расширения

**Возвращает**: Имя файла (например, `measurement_2025_11_03` для файла `C:\Data\measurement_2025_11_03.bin`)

**Использование**: Формирование имени при сохранении диапазона

#### 1b. DataModule::LoadDataFromFile() (обновлено v2.6.0)
```cpp
bool LoadDataFromFile(const std::wstring& filename);
```

**Обновления**:
- Сохраняет имя загруженного файла в переменную `loadedFileName`
- Извлекает имя файла из полного пути (удаляет путь к папке)
- Удаляет расширение `.bin` из имени
- Очищает `loadedFileName` при вызове `ClearData()`

#### 2. ChartManager::HandleSaveRange() (обновлено v2.6.0)
```cpp
void HandleSaveRange(HWND hWnd, int chartNumber);
```

**Назначение**: Обработка нажатия кнопки "Save Range"

**Параметры**:
- `hWnd` - handle главного окна
- `chartNumber` - номер графика (1 или 2)

**Алгоритм**:
```cpp
1. Проверка наличия загруженных данных
2. Проверка наличия установленного X Range
3. Получение индексов из ZoomRange
4. Формирование имени файла:
   - Получение имени исходного файла (GetLoadedFileName)
   - Получение текущей даты (GetLocalTime)
   - Формирование по шаблону: [имя]_range_[начало]_[конец]_[ДД_ММ_ГГГГ].bin
5. Открытие диалога сохранения файла (GetSaveFileName) с предложенным именем
6. Вызов DataModule::SaveDataRange()
7. Отображение сообщения об успехе/ошибке
```

**Обновления v2.6.0**:
- Автоматическое формирование информативного имени файла
- Добавление даты сохранения в формате ДД_ММ_ГГГГ
- Использование имени исходного файла в качестве базы

#### 3. UI Elements
**Кнопки**:
- `IDC_SAVE_RANGE1_BTN` (ID: 1036) - для Chart 1
- `IDC_SAVE_RANGE2_BTN` (ID: 1037) - для Chart 2

**Расположение**:
- Chart 1: справа от кнопки "Reset" в панели инструментов
- Chart 2: справа от кнопки "Reset" рядом с Device Schematic

**Размер**: 80x24 пикселей

**Текст**: "Save Range"

### Структура сохраненного файла

```
Исходный файл: measurement_2025_11_03.bin
Размер: 10000 записей GP_TOOL_DATA
Размер файла: 10000 * sizeof(GP_TOOL_DATA) = 10000 * 164 = 1,640,000 байт

X Range: From 5000 To 6000
Дата сохранения: 3 ноября 2025

Сохраненный файл: measurement_2025_11_03_range_5000_6000_03_11_2025.bin
Размер: 1001 запись GP_TOOL_DATA (индексы 5000-6000 включительно)
Размер файла: 1001 * 164 = 164,164 байт

Содержимое:
Запись 0: data[5000] из исходного файла
Запись 1: data[5001] из исходного файла
...
Запись 1000: data[6000] из исходного файла
```


## ✅ Валидация и проверки

### Проверки перед сохранением
1. **Наличие данных**: Проверяется `dataModule->HasData()`
2. **Установлен X Range**: Проверяется `zoom->isZoomed`
3. **Корректность индексов**: `startIndex <= endIndex < dataSize`

### Сообщения об ошибках
- "No data loaded!" - данные не загружены
- "Please set X Range first using Apply button!" - X Range не установлен
- "Invalid range indices!" - некорректные индексы
- "Failed to save data range!" - ошибка записи файла

### Сообщение об успехе
```
Successfully saved 1001 records (indices 5000 to 6000) to file:
C:\Data\data_range_5000_6000.bin
```

## ⚠️ Ограничения

1. **Формат файла**: Сохраняется только в формате GP_TOOL_DATA, другие форматы не поддерживаются
2. **Перенумерация**: В сохраненном файле индексы начинаются с 0 (исходная нумерация не сохраняется)
3. **Метаданные**: Информация об исходном файле и диапазоне не сохраняется в файле
4. **Размер**: Минимум 1 запись (startIndex == endIndex)
