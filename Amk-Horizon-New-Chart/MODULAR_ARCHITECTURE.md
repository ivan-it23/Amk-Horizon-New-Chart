# Модульная архитектура AMK-Horizon-Chart

## Обзор архитектуры

Проект был рефакторен с монолитной архитектуры на модульную для улучшения масштабируемости, сопровождаемости и разделения ответственности.

## Структура модулей

### 1. DataModule (DataModule.h/cpp)
**Ответственность**: Управление данными прибора
- Загрузка данных из бинарных файлов
- Хранение данных GP_TOOL_DATA
- Вычисления данных для графиков
- Определение типов данных и частотных диапазонов

**Ключевые методы**:
- `LoadDataFromFile()` - загрузка данных из файла
- `CalculateChartData()` - вычисление данных для отображения
- `GetDataTypeName()` - получение названий типов данных

### 2. ChartModule (ChartModule.h/cpp)
**Ответственность**: Отрисовка графиков
- Отрисовка фона, рамок и заголовков графиков
- Отрисовка осей координат
- Визуализация данных (линии, точки)
- Отрисовка легенды для многоканальных данных

**Ключевые методы**:
- `DrawChart()` - основной метод отрисовки графика
- `DrawChartData()` - отрисовка данных
- `DrawChartLegend()` - отрисовка легенды

### 3. UIModule (UIModule.h/cpp)
**Ответственность**: Управление пользовательским интерфейсом
- Создание элементов управления (кнопки, комбобоксы, чекбоксы)
- Обработка событий пользовательского интерфейса
- Управление состоянием элементов управления
- Управление видимостью элементов

**Ключевые методы**:
- `CreateControls()` - создание элементов управления
- `HandleCommand()` - обработка команд от элементов управления
- `UpdateControlsVisibility()` - управление видимостью
- `ToggleDualMode()` - переключение режимов

### 4. LayoutModule (LayoutModule.h/cpp)
**Ответственность**: Управление компоновкой интерфейса
- Расчет размеров и позиций графиков
- Валидация ограничений размеров окна
- Управление режимами отображения (одиночный/двойной)
- Расчет позиций элементов управления

**Ключевые методы**:
- `CalculateLayout()` - расчет компоновки
- `ValidateLayoutConstraints()` - валидация ограничений
- `GetChart1Rect()`, `GetChart2Rect()` - получение областей графиков

### 5. ChartManager (ChartManager.h/cpp)
**Ответственность**: Координация модулей и внешний интерфейс
- Создание и управление модулями
- Координация взаимодействия между модулями
- Предоставление единого интерфейса для главного окна приложения
- Управление масштабированием и интерактивностью графиков

## Преимущества модульной архитектуры

### 1. Разделение ответственности
- Каждый модуль отвечает за конкретную область функциональности
- Упрощение понимания и сопровождения кода
- Уменьшение связанности между компонентами

### 2. Масштабируемость
- Легкое добавление новых типов графиков (ChartModule)
- Простое расширение типов данных (DataModule)
- Возможность добавления новых элементов UI (UIModule)

### 3. Тестируемость
- Каждый модуль может быть протестирован независимо
- Возможность создания mock-объектов для тестирования
- Изоляция логики для unit-тестов

### 4. Повторное использование
- Модули могут быть использованы в других проектах
- Четкие интерфейсы между модулями
- Независимая разработка модулей

## Совместимость с существующим кодом

Рефакторинг был выполнен с сохранением полной совместимости:
- Все публичные методы ChartManager остались неизменными
- Поведение приложения полностью сохранено
- Существующий код главного окна не требует изменений
