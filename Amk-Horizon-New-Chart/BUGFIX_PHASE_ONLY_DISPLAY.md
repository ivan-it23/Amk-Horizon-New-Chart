# 🐛 Исправление отображения графиков только с фазами - Версия 2.6.3

**Дата**: 6 ноября 2025  
**Версия**: 2.6.3

## 📋 Описание проблемы

### Симптомы
При выборе в Device Schematic только фазовых кривых (без амплитуд) график оставался пустым и ничего не отображалось.

**Примеры проблемных ситуаций:**

#### Ситуация 1: Выбран приёмник R1, включены только фазы
- ☑ T1 Phase R1 (mdeg) [Right Axis] - включено
- ☑ T2 Phase R1 (mdeg) [Right Axis] - включено
- ☑ T3 Phase R1 (mdeg) [Right Axis] - включено
- ☑ T4 Phase R1 (mdeg) [Right Axis] - включено
- ☐ T1-T4 Amplitude R1 (mV) [Left Axis] - выключено

**Результат**: График пустой ❌

#### Ситуация 2: Выбран передатчик T1, включены только фазы
- ☐ T1 Amplitude R1 (mV) [Left Axis] - выключено
- ☑ T1 Phase R1 (mdeg) [Right Axis] - включено
- ☐ T1 Amplitude R2 (mV) [Left Axis] - выключено
- ☑ T1 Phase R2 (mdeg) [Right Axis] - включено

**Результат**: График пустой ❌

### Причина
Фазовые кривые назначались на **правую ось** (`yAxisGroup = 1`), а система отрисовки графиков не отображала данные, если на левой оси не было кривых. График требовал наличия данных на левой оси для корректного отображения.

## ✅ Решение

### Логика нормализации осей

Добавлена автоматическая нормализация осей в методе `CalculateCurveData`:

1. **Проверка включённых кривых**: Перед отрисовкой проверяется, есть ли включённые кривые на левой и правой осях
2. **Условие нормализации**: Если нет включённых кривых на левой оси, но есть на правой - включается нормализация
3. **Перемещение на левую ось**: Все кривые с правой оси перемещаются на левую ось
4. **Изменение стиля линии**: Линии меняются с пунктирных (PS_DASH) на сплошные (PS_SOLID)

### Код реализации

```cpp
// НОВОЕ v2.6.3: Нормализация осей
bool hasEnabledLeftAxis = false;
bool hasEnabledRightAxis = false;

for (const auto& curve : config.curves) {
    if (!curve.enabled) continue;
    if (curve.yAxisGroup == 0) hasEnabledLeftAxis = true;
    if (curve.yAxisGroup == 1) hasEnabledRightAxis = true;
}

// Если есть только кривые на правой оси, перемещаем их на левую
bool normalizeAxes = (!hasEnabledLeftAxis && hasEnabledRightAxis);

// При добавлении кривых
int effectiveAxisGroup = normalizeAxes ? 0 : curve.yAxisGroup;

if (effectiveAxisGroup == 0) {
    leftAxisData.push_back(curveData);
    CurveDefinition normalizedCurve = curve;
    normalizedCurve.yAxisGroup = 0;
    normalizedCurve.lineStyle = PS_SOLID; // Сплошная линия
    leftAxisCurves.push_back(normalizedCurve);
}
```

## 📊 Результат

### После исправления

#### Ситуация 1: Выбран R1, включены только фазы
**Отображение**: График показывает 4 кривые фаз (T1-T4 Phase R1) на левой оси со сплошными линиями ✅

#### Ситуация 2: Выбран T1, включены только фазы
**Отображение**: График показывает 2 кривые фаз (T1 Phase R1, T1 Phase R2) на левой оси со сплошными линиями ✅

#### Ситуация 3: Включены и фазы, и амплитуды
**Отображение**: Амплитуды на левой оси (сплошные), фазы на правой оси (пунктирные) - как и раньше ✅

## 🔧 Технические детали

### Изменённые методы

#### CurveSelectionModule::CalculateCurveData() (обе перегрузки)
- Добавлена проверка наличия включённых кривых на каждой оси
- Добавлен флаг `normalizeAxes` для определения необходимости нормализации
- Кривые с правой оси автоматически перемещаются на левую при нормализации
- Стиль линии меняется на сплошной (PS_SOLID) для левой оси

### Применяется к
- **Одиночный приёмник** (R1 или R2) - только фазы
- **Передатчики** (T1-T4) - только фазы для R1 и/или R2
- **Любая комбинация** - где включены только фазовые кривые

### Не затрагивает
- **Нормальный режим** - когда есть и амплитуды, и фазы (работает как раньше)
- **Только амплитуды** - работает как раньше
- **R1+R2** (Ratios & Differences) - работает как раньше

## ✅ Преимущества

### 1. Корректное отображение
- Фазовые кривые теперь всегда отображаются, даже без амплитуд
- График не остаётся пустым при выборе только фаз
- Пользователь видит данные, которые он выбрал

### 2. Автоматическая адаптация
- Система автоматически определяет, нужна ли нормализация
- Не требуется ручная настройка осей
- Работает для всех комбинаций выбора элементов

### 3. Визуальная согласованность
- Сплошные линии для единственной оси (как для амплитуд)
- Пунктирные линии только когда есть две оси
- Логичное и понятное отображение

### 4. Обратная совместимость
- Не влияет на существующие конфигурации с обеими осями
- Старые графики отображаются как раньше
- Изменения применяются только при необходимости
