# Анализ форматов файлов данных: .bin, .biv, .DEV

> Статус: актуально для текущей версии приложения (5Tx, 240 байт `GP_TOOL_DATA`).

## Введение

Данный документ описывает логику чтения файлов с расширениями `.bin`, `.biv` и `.DEV` в проекте AMK-Horizon-New-Chart. Анализ построен на сравнении с базовым форматом `.bin`, который является наиболее простым для понимания.

---

## 1. Структура данных GP_TOOL_DATA (актуальная 5Tx)

Все форматы файлов хранят данные в виде структуры `GP_TOOL_DATA`:

```cpp
struct GP_TOOL_DATA { // 240 bytes
    uint32_t signature;
    uint32_t condition;
    uint32_t frame;
    float temperature;
    float rho_smt[2][5];
    float phase_smt[2][5];
    float AM_RX_1[2][5];
    float ZERO_AM_RX_1[2];
    float AM_RX_2[2][5];
    float ZERO_AM_RX_2[2];
    float DELTA_PH[2][5];
    float ZERO_dPH[2];
};
```

**Сигнатура**
- Поле `signature` используется как идентификатор прибора/модификации и для валидации.
- Точное множество допустимых сигнатур зависит от прибора/эмулятора.

## 2. Формат .bin (базовый)

### 2.1 Структура файла

Файл `.bin` — это **последовательность структур GP_TOOL_DATA без заголовков и разделителей**.

```
┌─────────────────────────────────────────────────────────────┐
│                        ФАЙЛ .bin                            │
├─────────────────────────────────────────────────────────────┤
│  Кадр 0: GP_TOOL_DATA (240 байт)                           │
│  Смещение: 0                                                │
├─────────────────────────────────────────────────────────────┤
│  Кадр 1: GP_TOOL_DATA (240 байт)                           │
│  Смещение: 240                                              │
├─────────────────────────────────────────────────────────────┤
│  Кадр 2: GP_TOOL_DATA (240 байт)                           │
│  Смещение: 480                                              │
├─────────────────────────────────────────────────────────────┤
│  ...                                                        │
├─────────────────────────────────────────────────────────────┤
│  Кадр N: GP_TOOL_DATA (240 байт)                           │
│  Смещение: N * 240                                          │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 Функция чтения

```cpp
GP_TOOL_DATA READ_BLOK_AllData_1DDS(ifstream &fin, int n) {
    GP_TOOL_DATA P;
    fin.seekg(n * sizeof(GP_TOOL_DATA));        // Переход к n-му кадру (n * 240)
    fin.read((char*)&P, sizeof(GP_TOOL_DATA));  // Чтение 240 байт
    return P;
}
```

### 2.3 Определение количества кадров

```cpp
fin.seekg(0, ios::end);                         // Переход в конец файла
Co = int(fin.tellg()) / sizeof GP_TOOL_DATA;    // Размер файла / 240
```

### 2.4 Алгоритм чтения

1. Открыть файл в бинарном режиме
2. Определить количество кадров: `размер_файла / 240`
3. В цикле читать каждый кадр (240 байт)

*Примечание:* в структуре `GP_TOOL_DATA` присутствует поле `signature`, его можно использовать для валидации данных, но в текущей реализации проекта формат файла определяется по расширению.

**Пример кода:**
```cpp
if (extension == ".bin" || extension == ".biv") {
    fin.open(Data, ios::binary);
    fin.seekg(0, ios::end);
    Co = int(fin.tellg()) / sizeof GP_TOOL_DATA; // Количество кадров
    fin.close();
    
    fin.open(Data, ios::binary);
    for (int n = 0; n < Co; n++) {
        DAT S;
        S.GP = READ_BLOK_AllData_1DDS(fin, n);   // Читаем n-й кадр
        DATA1.push_back(S);
    }
    fin.close();
}
```

## 3. Формат .biv

### 3.1 Структура файла

Формат `.biv` **полностью идентичен формату `.bin`**. В коде они обрабатываются одинаково:

```cpp
if (extension == ".bin" || extension == ".biv") {
    // Одинаковая логика чтения
}
```

### 3.2 Сравнение с .bin

| Параметр | .bin | .biv |
|----------|------|------|
| Структура файла | Последовательность GP_TOOL_DATA | Последовательность GP_TOOL_DATA |
| Размер кадра | 240 байт | 240 байт |
| Заголовок файла | Нет | Нет |
| Заголовок кадра | Нет | Нет |
| Функция чтения | READ_BLOK_AllData_1DDS() | READ_BLOK_AllData_1DDS() |
| Формула смещения | n * 240 | n * 240 |

**Вывод:** `.biv` — это просто альтернативное расширение для файлов того же формата, что и `.bin`. Возможно, используется для различения источников данных или версий программного обеспечения.

## 4. Формат .DEV

### 4.1 Структура файла

Формат `.DEV` отличается от `.bin` наличием **11-байтного служебного заголовка перед каждым кадром данных**.

По методическим материалам (см. `Методичка-фото-2.png`) эти 11 байт добавляются для внешней программной совместимости: «к структуре данных присоединяется 11 служебных байт».

```
┌─────────────────────────────────────────────────────────────┐
│                        ФАЙЛ .DEV                            │
├─────────────────────────────────────────────────────────────┤
│  Кадр 0:                                                    │
│    ├── Заголовок (11 байт)                                 │
│    └── GP_TOOL_DATA (240 байт)                             │
│  Смещение данных: 11                                        │
│  Общий размер блока: 251 байт                              │
├─────────────────────────────────────────────────────────────┤
│  Кадр 1:                                                    │
│    ├── Заголовок (11 байт)                                 │
│    └── GP_TOOL_DATA (240 байт)                             │
│  Смещение данных: 251 + 11 = 262                           │
│  Общий размер блока: 251 байт                              │
├─────────────────────────────────────────────────────────────┤
│  Кадр 2:                                                    │
│    ├── Заголовок (11 байт)                                 │
│    └── GP_TOOL_DATA (240 байт)                             │
│  Смещение данных: 502 + 11 = 513                           │
├─────────────────────────────────────────────────────────────┤
│  ...                                                        │
├─────────────────────────────────────────────────────────────┤
│  Кадр N:                                                    │
│    ├── Заголовок (11 байт)                                 │
│    └── GP_TOOL_DATA (240 байт)                             │
│  Смещение данных: N * 251 + 11                             │
└─────────────────────────────────────────────────────────────┘
```

### 4.2 Функция чтения

```cpp
GP_TOOL_DATA READ_BLOK_AllData_1DDS_Oleg(ifstream &fin, int n) {
    GP_TOOL_DATA P;
    uint8_t *buff = new uint8_t[12];
    
    // Переход к n-му блоку (каждый блок = 240 + 11 = 251 байт)
    fin.seekg(n * (sizeof(GP_TOOL_DATA) + 11));
    
    // Пропуск 11-байтного заголовка
    fin.read((char*)buff, 11);
    
    // Чтение данных GP_TOOL_DATA
    fin.read((char*)&P, sizeof(GP_TOOL_DATA));
    
    return P;
}
```

### 4.3 Определение количества кадров

```cpp
fin.seekg(0, ios::end);
Co = int(fin.tellg()) / (sizeof GP_TOOL_DATA + 11);  // Размер файла / 251
```

### 4.4 Проверка сигнатуры

В текущей реализации проекта определение формата выполняется по расширению файла (см. `DataModule::DetectFileFormat`). Для `.DEV` заголовок кадра пропускается и читается блок данных `GP_TOOL_DATA`.

### 4.5 Сравнение с .bin

| Параметр | .bin | .DEV |
|----------|------|------|
| Структура файла | Только данные | Заголовок + данные |
| Размер кадра данных | 240 байт | 240 байт |
| Заголовок кадра | Нет | 11 байт |
| Общий размер блока | 240 байт | 251 байт |
| Функция чтения | READ_BLOK_AllData_1DDS() | READ_BLOK_AllData_1DDS_Oleg() |
| Формула смещения | n * 240 | n * 251 |
| Смещение данных в блоке | 0 | 11 |

## 5. Визуальное сравнение форматов

### 5.1 Схема расположения данных

```
ФОРМАТ .bin / .biv:
┌────────────────────────────────────────────────────────────────────┐
│ Байт:  0        240       480       720       960      1200       │
│        │         │         │         │         │         │        │
│        ▼         ▼         ▼         ▼         ▼         ▼        │
│       ┌─────────┬─────────┬─────────┬─────────┬─────────┬─────── │
│       │ Кадр 0  │ Кадр 1  │ Кадр 2  │ Кадр 3  │ Кадр 4  │ ...    │
│       │ 240 б   │ 240 б   │ 240 б   │ 240 б   │ 240 б   │        │
│       └─────────┴─────────┴─────────┴─────────┴─────────┴─────── │

┌────────────────────────────────────────────────────────────────────┐

│        │   │         │   │         │   │         │   │            │
│        ▼   ▼         ▼   ▼         ▼   ▼         ▼   ▼            │
│       ┌───┬─────────┬───┬─────────┬───┬─────────┬───┬─────────┬── │

```

### 5.2 Формулы для вычисления смещений

| Формат | Смещение n-го кадра | Смещение данных в кадре |
|--------|---------------------|-------------------------|
| .bin   | `n * 240`           | 0                       |
| .biv   | `n * 240`           | 0                       |
| .DEV   | `n * 251`           | 11                      |

## 6. Алгоритм определения формата файла

```cpp
// Псевдокод определения формата и чтения файла

void ReadDataFile(string filename) {
    string extension = GetExtension(filename);
    ifstream fin(filename, ios::binary);
    uint32_t signature;
    int frameCount;
    
    if (extension == ".bin" || extension == ".biv") {
        // Читаем сигнатуру с начала файла
        fin.read((char*)&signature, 4);
        
        // Определяем количество кадров
        fin.seekg(0, ios::end);
        frameCount = fin.tellg() / 240;
        
        // Читаем кадры
        for (int n = 0; n < frameCount; n++) {
            fin.seekg(n * 240);
            GP_TOOL_DATA data;
            fin.read((char*)&data, 240);
            // Обработка data...
        }
    }
    else if (extension == ".DEV") {
        // Определяем количество кадров
        fin.seekg(0, ios::end);
        frameCount = fin.tellg() / 251;

        // Читаем кадры
        for (int n = 0; n < frameCount; n++) {
            fin.seekg(n * 251);       // Переход к началу блока
            fin.seekg(11, ios::cur);  // Пропуск 11-байтного заголовка кадра

            GP_TOOL_DATA data;
            fin.read((char*)&data, 240);
            // Обработка data...
        }
    }
    
    fin.close();
}
```

## 7. Содержимое 11-байтного заголовка .DEV

В текущей реализации приложения содержимое заголовка **не используется** — оно просто пропускается при чтении:

```cpp
uint8_t *buff = new uint8_t[12];
fin.read((char*)buff, 11);  // Заголовок читается, но не обрабатывается
```

**Предположительная структура заголовка** (требует уточнения):
- Возможно содержит метаданные кадра
- Временные метки
- Служебную информацию от устройства записи

## 9. Рекомендации для разработки

1. **При добавлении нового формата:**
   - Определите структуру заголовка (если есть)
   - Создайте отдельную функцию чтения по аналогии с существующими
   - Добавьте расширение в фильтр диалога открытия файла

2. **При работе с .DEV файлами:**
   - Учитывайте 11-байтный заголовок при расчете смещений
   - Размер блока = 251 байт, не 240

3. **Проверка целостности:**
   - Всегда проверяйте размер/кратность кадров выбранному формату.
   - При необходимости дополнительно валидируйте поле `signature`, но не привязывайтесь к фиксированному набору legacy-значений: допустимые значения зависят от прибора/прошивки/эмулятора.
