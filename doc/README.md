# AMK-Horizon-New-Chart

> Актуально для текущей ветки `main`.
>
> Этот файл — **главная точка входа в проект**. Если нужен быстрый и надёжный контекст, начинайте с него, затем переходите к `TECHNICAL_REFERENCE.md`, `ANALYSIS_GP_TOOL_DATA.md` и `PROJECT_STATUS.md`.

## Что это за проект

`AMK-Horizon-New-Chart` — Win32 C++ приложение для загрузки, онлайн-опроса, визуализации и анализа данных геофизических приборов семейств Автоном и LWD (3Tx, 4Tx, 5Tx и любые будущие конфигурации).

Приложение умеет:

- открывать файлы `.bin`, `.biv`, `.DEV`;
- опрашивать прибор по COM, записывать поток кадров в файл (папка и имя по правилам метрологии);
- строить графики по нескольким типам данных;
- работать с немодальной схемой прибора и пресетами кривых;
- читать/писать метрологию для поддерживаемых сценариев;
- хранить заметки, привязанные к конфигурации графика;
- вести **немодальный лог обмена с прибором** (COM TX/RX, успешные кадры, идентификация прибора) с удобной прокруткой.

## Актуальная архитектура

Проект построен вокруг `ChartManager`, который координирует модули:

- `DataModule`
- `ChartModule`
- `UIModule`
- `LayoutModule`
- `SchematicModule`
- `CurveSelectionModule`
- `SerialModule`
- `MetrologyModule`
- `NotesModule`
- `AsyncTaskQueue`
- `DeviceExchangeLog` / `DeviceLogPanel` — буфер строк лога и UI-панель (док у верхнего края окна, развёрнутое окно)

### Актуальный pipeline данных

Текущее движение данных в проекте:

`File / COM -> ToolDataAdapterRegistry -> ParsedToolFrame -> canonical GP_TOOL_DATA + ToolRecordMetadata -> ToolDataAccessView / MeasurementView -> chart / UI logic`

Ключевые свойства этой модели:

- вход по файлам и COM уже маршрутизируется через `ToolDataAdapterRegistry`;
- `ParsedToolFrame` несёт `kind`, `capabilities` и `canonicalData`;
- `DataModule` хранит записи как `GP_TOOL_DATA` плюс `ToolRecordMetadata`;
- верхние слои постепенно опираются на `ToolDataAccessView` и `MeasurementView`;
- canonical `GP_TOOL_DATA` пока остаётся основной compatibility storage/API shape.

## Поддерживаемые структуры и форматы

### Поддерживаемые типы приборов

Тип прибора и число передатчиков определяются динамически из palette (toolCode = XYZ):
- **X** — тип прибора: `1` = Автоном, `2` = LWD
- **Y** — число передатчиков: `3`, `4`, `5`
- **Z** — модификация

Примеры: `151` (Автоном 5Tx мод1), `242` (LWD 4Tx мод2), `231` (LWD 3Tx мод1).

Система масштабируема: новые комбинации toolCode поддерживаются автоматически без изменения кода.

### Поддерживаемые контейнеры

- `.bin`
- `.biv`
- `.DEV`

Физический размер кадра:

- `.bin/.biv` — `240` байт полезной нагрузки;
- `.DEV` — `11` байт заголовка + `240` байт payload = `251` байт на физический кадр.

## Главные пользовательские возможности

### Графики и навигация

- один или два графика одновременно;
- одинарная и двойная Y-ось;
- zoom по X и Y;
- скроллинг;
- отображение по `FRAME_NUMBER` и по `TEMPERATURE`;
- режим `Surf`;
- корректная работа на больших наборах данных;
- заметки, привязанные к конфигурации и экранной геометрии графика.

### Кривые и схема прибора

- ручной выбор через схему прибора;
- быстрые пресеты:
  - все амплитуды для `R1`;
  - все амплитуды для `R2`;
  - отношения амплитуд;
  - разности фаз;
  - silent-амплитуды;
  - silent-разность фаз;
  - температура;
  - `УЭС`;
  - `Симм. фазы`;
- выбор частоты `400 кГц / 2000 кГц`;
- копирование конфигурации между графиками;
- автоматическое обновление цветов кривых.

### Runtime поддержка 3Tx/4Tx/5Tx в UI

- визуальная схема использует 5 фиксированных слотов `T1..T5`;
- **доступность передатчиков определяется динамически** из palette через `ToolCapabilities.transmitterCount`;
- недоступные передатчики в схеме отображаются как заблокированные, их кривые не появляются в списке.

### Цветовая логика кривых

В `CurveSelectionModule` действует централизованное назначение цветов через `RefreshCurveColors(...)`.

Текущие инварианты:

- цвета перераспределяются на весь набор кривых, а не выдаются локально по одной;
- для `T1..T4` закреплены приоритетные корпоративные цвета:
  - `T1` — мягкий зелёный;
  - `T2` — мягкий жёлтый;
  - `T3` — мягкий красный;
  - `T4` — мягкий синий;
- остальные цвета добираются из расширенной и процедурной палитры;
- палитра намеренно приглушена для комфортной длительной работы.

### Подключение и опрос прибора

- быстрое подключение/отключение через toggle-кнопку **Включить / Отключить** (зелёная/красная) на панели управления;
- кнопка использует сохранённые настройки последнего COM-порта;
- если порт не сохранён — показывается информационное сообщение с предложением открыть "Настройки подключения...";
- опрос прибора через кнопку с иконкой **▶ / ■** (Старт/Стоп) рядом с кнопкой подключения;
- меню **«Настройки подключения…»** для расширенной конфигурации COM-порта, интервала опроса и папки записи;
- автоматическое сохранение последнего использованного COM-порта и папки записи между сессиями (см. раздел «Сохранение настроек»);
- индикация состояния подключения и опроса через цвет кнопок и tooltip-ы;
- быстрое подключение по сохранённому порту с панели — `ChartManager::HandleSerialConnectQuick` (проверка `LoadLastUsedComPort()` и списка портов); полная настройка COM — немодальный диалог в `Amk-Horizon-New-Chart.cpp` (меню **«Настройки подключения…»**).

### Лог обмена с прибором (отладка COM)

- пункт меню **«Логи»** открывает **немодальную** панель лога: не блокирует работу с графиком.
- Панель позиционируется у верхнего края главного окна, между кнопкой подключения и элементом курсора/сброса; нижний край слегка заходит на область графика, но **не перекрывает** подписи легенды (согласовано с отрисовкой в `ChartModule`).
- В лог пишутся строки протокола: исходящие/входящие пакеты (**TX** / **RX**), успешные кадры с полями **signature**, **condition**, **frame** и температурой, сообщения метрологии, события COM.
- После первого успешного чтения метрологии в лог добавляется выделенный блок **идентификации прибора** (тип по адаптеру, число передатчиков, серийный номер) — отображается **жирным** при использовании Rich Edit (`Msftedit.dll` / `RichEdit50W`); при недоступности Rich Edit текст остаётся обычным.
- Кнопки **«Очистить»**, **«Развернуть»** (крупное окно по центру экрана с **«Свернуть»**), полоса прокрутки.
- Поведение прокрутки: по умолчанию и при «приклеивании к низу» показываются **последние** записи; при просмотре истории выше позиция сохраняется; после возврата скролла вниз новые строки снова дописываются в конец без «прыжка» к началу (в т.ч. инкрементальное дописывание и доразмеривание панели в `DeviceLogPanel_UpdateLayout`).

### Сохранение настроек

Файл настроек (UTF-8, строки `ключ=значение`):

- путь: `%LOCALAPPDATA%\AMK-Horizon-New-Chart\app_settings.txt` (полный путь: `%USERPROFILE%\AppData\Local\AMK-Horizon-New-Chart\app_settings.txt`);
- ключи включают как минимум: `lastComPort`, `lastRecordFolder`.

Удаление или правка файла используется для проверки сценариев «порт не сохранён» и сброса путей.

### COM и метрология

- COM-протокол использует пакет:
  - `[CMD:1][LEN:2][PAYLOAD][CRC16:2]`
- рабочие команды:
  - `0x11` — данные;
  - `0x12` — запись метрологии;
  - `0x13` — чтение метрологии;
  - `0x16` — сигнатура;
  - `0x17` — `selected_key`;
- рабочая скорость: `125000` бод;
- realtime in-tree path использует `ParsedToolFrame` и metadata-backed ingest.

## Важные текущие UI-инварианты

### `X Range` и `Surf`

Текущее поведение считается обязательным:

- поля `X Range` **не должны самопроизвольно перезаписывать пользовательский ввод** до явного применения;
- в COM polling режиме пользователь может задать только `From`, а `To` оставить пустым;
- это означает режим `From .. latest frame`, где правая граница автоматически следует за последними кадрами;
- в `Surf` поля `X Range` тоже не должны авто-подставляться поверх пользовательского ввода.

### Заметки

`NotesModule` хранит заметки как sidecar-данные, привязанные к:

- конфигурации кривых;
- типу оси X;
- индексу кадра;
- значениям левой/правой оси.

Заметки не являются отдельным историческим архивом графика — они привязаны к текущей конфигурационной модели.

## Что важно для разработчика

### Куда смотреть в коде

- `ChartManager.*` — общая orchestration логика, zoom, scroll, render pipeline, live path, export, notes;
- `DataModule.*` — file loading, canonical storage, range metadata, export seams;
- `ToolDataAdapters.*` — adapter-driven parsing и маршрутизация по структурам;
- `ToolDataAccess.h` — `ToolDataAccessView`, `MeasurementView`;
- `CurveSelectionModule.*` — сборка конфигураций кривых, SMT, цвета;
- `SchematicModule.*` — схема прибора, ручной выбор, пресеты, runtime `4Tx/5Tx` UI-ограничения;
- `SerialModule.*` — COM-протокол, polling, callbacks, метрология;
- `MetrologyModule.*` — работа с формой метрологии;
- `NotesModule.*` — загрузка/сохранение заметок и hit-test маркеров;
- `DeviceExchangeLog.*` — потокобезопасный буфер строк лога, уведомление главного окна (`WM_APP_DEVICE_LOG_REFRESH`);
- `DeviceLogPanel.*` — док-панель и развёрнутое окно, Rich Edit или обычный `EDIT`, синхронизация с буфером.

### Актуальные архитектурные особенности

- все приборы используют единую структуру `GP_TOOL_DATA` (240 байт);
- legacy `LEGACY_GP_TOOL_DATA` и legacy COM-протокол (CMD 0x65/0x66/0x67) удалены;
- один `UniversalCanonicalAdapter` обрабатывает все типы приборов;
- `SaveDataRange(...)` сохраняет canonical `.bin`;
- computer-side `SMT` в `FROM_COMPUTER` остаётся legacy-compatible вычислительной веткой.

## Быстрый старт

### Сборка

1. Откройте `Amk-Horizon-New-Chart.vcxproj` в Visual Studio.
2. Выберите `Debug` или `Release`, `x64`.
3. Выполните сборку решения.

### Запуск

1. Запустите приложение.
2. Откройте файл данных или подключитесь к прибору по COM.
3. Настройте отображение через схему прибора или пресеты.
4. При необходимости включите заметки, экспорт диапазона или метрологические операции.
