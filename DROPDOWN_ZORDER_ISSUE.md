# Техническое задание: Проблема Z-порядка выпадающих списков второго графика

## Описание проблемы

### Основная проблема
В режиме двух графиков выпадающие списки панели управления второго графика (выбор типа данных и частоты) **не отображаются поверх** второго графика. При нажатии на выпадающие списки их содержимое остается **невидимым** для пользователя, так как перекрывается областью отрисовки второго графика.

**Контраст поведения:**
- ✅ **Первый график**: Выпадающие списки работают корректно, отображаются поверх всех элементов
- ❌ **Второй график**: Выпадающие списки невидимы, перекрываются графиком

## Технические гипотезы проблемы

### Гипотеза №1: Проблема Z-порядка окон
**Описание:** Элементы управления второго графика имеют неправильный Z-порядок относительно области отрисовки.

**Свидетельства:**
- Использование `WS_EX_TOPMOST` не решило проблему
- Использование `HWND_TOP` в `SetWindowPos()` не помогло
- Различные методы создания окон (CreateWindow vs CreateWindowEx)

### Гипотеза №2: Конфликт области отрисовки
**Описание:** Операция `FillRect()` второго графика перерисовывает область выпадающих списков.

**Свидетельства:**
- Первый график не имеет элементов управления в области отрисовки
- Второй график отрисовывается после позиционирования элементов управления
- Заливка фона происходит перед отрисовкой графика

### Гипотеза №3: Проблема последовательности сообщений
**Описание:** Сообщения Windows обрабатываются в неправильном порядке.

**Свидетельства:**
- `InvalidateRect(hWnd, NULL, TRUE)` вызывается после изменений
- WM_PAINT обрабатывается после WM_SIZE
- Возможный конфликт между перерисовкой и позиционированием

### Гипотеза №4: Проблема клиппинга области
**Описание:** Выпадающие списки ограничиваются областью родительского окна некорректно.

**Свидетельства:**
- Возможное влияние флагов стилей окна
- Различия в обработке дочерних окон
- Проблемы с координатами относительно клиентской области

## Направления для решения

### Подход №1: Исключение области элементов управления из отрисовки
**Идея:** Модифицировать логику отрисовки, чтобы она не затрагивала области элементов управления.

**Области исследования:**
- Использование `ExcludeClipRect()` перед отрисовкой графика
- Точный расчет области отрисовки с учетом элементов управления
- Изменение порядка операций отрисовки

### Подход №2: Изменение архитектуры отрисовки
**Идея:** Изменить подход к отрисовке графиков, используя совместимый с элементами управления метод.

**Области исследования:**
- Отрисовка в память (off-screen) с последующим копированием
- Использование `UpdateWindow()` вместо `InvalidateRect()`
- Селективная отрисовка только изменившихся областей

### Подход №3: Реорганизация иерархии окон
**Идея:** Создать отдельные дочерние окна для каждого графика.

**Области исследования:**
- Создание отдельного окна для каждого графика
- Размещение элементов управления поверх графических окон
- Использование `WS_EX_TRANSPARENT` для элементов управления

### Подход №4: Изменение временной последовательности
**Идея:** Изменить порядок и время выполнения операций отрисовки и позиционирования.

**Области исследования:**
- Отложенная отрисовка после завершения позиционирования
- Использование таймеров для разделения операций
- Обработка WM_PAINT с учетом состояния элементов управления
